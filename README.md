# Forma

## Назначение

Forma — локальный редактор композиций из готовой библиотеки SVG. Он выбирает существующие объекты по теме либо по перечисленным названиям, автоматически раскладывает их на холсте и оставляет результат полностью редактируемым. Приложение не рисует новые иллюстрации, не растеризует исходники и не принимает геометрию от LLM.

## Возможности

- 20 проверенных assets, извлечённых из предоставленного `Размер L edited.svg`; в них сохранены 1552 исходных path в исходном порядке.
- Сборка по теме через настраиваемый OpenAI-compatible endpoint с автоматическим локальным fallback.
- Полностью локальная сборка по русским/английским названиям, синонимам и разделителям.
- Шаблоны `Сбалансированный`, `Главный объект` и `Диагональ`; автоматический масштаб без наложений.
- Добавление, выбор, drag-and-drop, позиция, масштаб, вращение, дублирование, удаление и порядок слоёв.
- Три размера холста, три палитры и три готовые демонстрационные композиции.
- Экспорт редактируемого векторного SVG с исходными path, viewBox и трансформациями.

## Стек

React 18, TypeScript, Vite, Vitest/jsdom и минимальный Node.js HTTP proxy без серверного фреймворка. Runtime-зависимости ограничены React и `lucide-react`.

## Требования

- Node.js 20 или новее;
- npm 10 или совместимая версия;
- современный браузер с поддержкой SVG и Pointer Events.

## Установка и запуск

```powershell
cd path\to\Forma
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. Команда запускает два локальных процесса: Vite и серверный API proxy на `http://127.0.0.1:8787`. Перед стартом pipeline заново проверяет и извлекает assets из исходного SVG.

### Режим разработки

- `npm run dev` — клиент и API proxy вместе, рекомендуемый запуск.
- `npm run dev:client` — только Vite; запрос по теме перейдёт на локальный fallback, потому что proxy недоступен.
- `npm run server` — только API proxy.

### Проверка production-сборки

```powershell
npm run build
npm run preview
```

После сборки preview доступен на `http://127.0.0.1:4173`; `/api` проксируется в тот же локальный backend.

## Режим без API

Никакая настройка не обязательна. Если `.env` отсутствует, endpoint/model не заданы, proxy недоступен, endpoint отвечает ошибкой либо его ответ не проходит whitelist, Forma использует существующий локальный словарь и тематические правила. Интерфейс показывает режим **«локальная эвристика — LLM не использована»**; это намеренно не называется полноценным ИИ.

Сценарий «По объектам» всегда локальный и никогда не обращается к LLM.

## Настройка LLM

LLM не требуется для запуска. Чтобы подключить OpenRouter, скопируйте шаблон и заполните его собственными серверными значениями:

```powershell
Copy-Item .env.example .env
```

На macOS/Linux эквивалентная команда: `cp .env.example .env`.

В созданном `.env` укажите:

```dotenv
FORMA_LLM_ENDPOINT=https://openrouter.ai/api/v1/chat/completions
FORMA_LLM_MODEL=provider/model-id
FORMA_LLM_API_KEY=your-own-key
FORMA_LLM_TIMEOUT_MS=20000
```

`provider/model-id` нужно заменить на выбранный в OpenRouter ID модели, а `your-own-key` — на собственный ключ проверяющего. Репозиторий и архив сдачи не содержат рабочего ключа. Endpoint и Bearer-аутентификация соответствуют [официальному OpenRouter Chat Completions API](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion).

Перезапустите `npm run dev`: конфигурация читается при старте backend. Без `.env` или с пустым `FORMA_LLM_MODEL` интеграция остаётся выключенной и используется локальная эвристика.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `FORMA_LLM_ENDPOINT` | Полный URL OpenAI-compatible `chat/completions`; в шаблоне указан endpoint OpenRouter |
| `FORMA_LLM_MODEL` | ID выбранной модели OpenRouter в формате `provider/model-id` |
| `FORMA_LLM_API_KEY` | Собственный OpenRouter Bearer key; пустой допустим только для keyless локального endpoint |
| `FORMA_LLM_TIMEOUT_MS` | Timeout upstream-запроса, по умолчанию 20000 мс; допустимо 1000–60000 |

Не переименовывайте их в `VITE_*`: такие переменные Vite может включить в клиентский bundle. `.env` и все его варианты исключены через `.gitignore`, кроме безопасного `.env.example`.

### Контракт и безопасность

1. Браузер отправляет локальному proxy только текст темы.
2. Proxy читает реальный manifest и передаёт модели разрешённый каталог с ID и метаданными.
3. Модель должна вернуть только JSON вида `{"objects":[{"id":"book","role":"knowledge"}]}`.
4. Сервер строго отклоняет лишние поля, ID вне manifest, SVG, path, image, URL, разметку и более восьми объектов.
5. Клиент повторно валидирует безопасный ответ по загруженному manifest и только затем запускает обычный локальный layout.

API key существует только в Node-процессе и передаётся upstream как Bearer header. В bundle, запрос браузера и сообщения об ошибках он не попадает. Геометрия всегда берётся из локального `SvgAsset`; ответ модели не может добавить path или изображение.

Если endpoint удалённый, текст темы и текстовые метаданные manifest отправляются выбранному провайдеру; исходные SVG и API key в prompt не передаются.

Серверная схема следует официальным рекомендациям не помещать API key в браузер и передавать его через Bearer authentication: [OpenAI API overview](https://developers.openai.com/api/reference/overview). Формат запроса описан в [Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); `json_object` дополняется обязательной собственной whitelist-валидацией.

## Как проверить оба сценария

### По теме или метафоре

1. Выберите **«По теме»**.
2. Введите, например, `Свет знаний и новые идеи`.
3. Выберите шаблон и нажмите **«Собрать композицию»**.
4. При настроенном и валидно ответившем endpoint статус покажет **LLM через локальный серверный proxy**. Без него статус явно покажет локальную эвристику.
5. Нажмите **«Пересобрать композицию»**: объекты и layout заменят прежнюю автоматическую сцену, сохранив размер холста и палитру.

### По названиям объектов

1. Выберите **«По объектам»**.
2. Введите, например, `книга, настольная лампа; flowers / phone`.
3. Нажмите **«Собрать композицию»**.
4. Проверьте, что найдены только реальные assets. Неизвестные названия перечисляются явно; найденная часть может быть собрана без выдуманных объектов.

Поддерживаются русский и английский языки, синонимы, запятые, `;`, новые строки, `/`, `\`, `+`, `&`, `|`, `и`, `плюс` и `and`.

## Демонстрационные композиции

Кнопки над холстом загружают три проверенных preset:

1. **Ideas that connect** — landscape, Lavender.
2. **A calmer workspace** — square, Peach.
3. **On the same wavelength** — landscape, Mint.

Автотест проверяет все ссылки на manifest, палитры и размеры, rotation-aware границы объектов, порядок слоёв и сохранность path при экспорте каждого preset.

В репозитории приложены три SVG, экспортированные через редактор:

- [`initial.svg`](examples/initial.svg) — 3 редактируемых слоя;
- [`music.svg`](examples/music.svg) — 5 редактируемых слоёв;
- [`tecnologies.svg`](examples/tecnologies.svg) — 6 редактируемых слоёв.

Все примеры содержат только исходные path из asset manifest, текущие трансформации и фон холста; растровых изображений и внешних иллюстраций нет.

## Палитры и исходные SVG

`Lavender` воспроизводит шесть исходных chromatic swatches. `Peach` и `Mint` заменяют их по тем же двум цветовым колонкам/ролям; чёрный и белый остаются неизменными. `background` в manifest означает silhouette-вариант объекта, а не правило принудительно красить весь asset одной группой: foreground-иллюстрации корректно используют цвета обеих колонок.

Аудит источников, неоднозначностей и исключённых 26 не-asset path описан в [ASSET_ANALYSIS.md](ASSET_ANALYSIS.md). Pipeline хранится в `scripts/extract-assets.mjs`, а стабильные диапазоны исходных элементов — в `src/data/verified-assets.json`.

## Экспорт SVG

Кнопка **Export SVG** создаёт XML SVG с размером текущего холста. Каждый объект остаётся отдельным `<g>`-слоем с `data-asset-id`, transform и вложенным SVG с исходным viewBox. Внутри остаются исходные `<path>`; растровых `<image>`, `foreignObject`, внешних ссылок и сгенерированной геометрии нет. Файл можно открыть в Inkscape, Illustrator или другом векторном редакторе.

## Тесты

```powershell
npm test
npm run build
```

Набор покрывает extraction/loader, все реальные path, палитры, layout, оба сценария автосборки, серверный и клиентский whitelist LLM, локальный fallback, ручные трансформации, три demo и SVG export. HTTP-интеграционный тест поднимает локальный mock OpenAI-compatible endpoint и проходит весь proxy-маршрут; внешний провайдер без пользовательских credentials тестами не вызывается.

## Структура проекта

- `src/App.tsx` — существующий редактор и orchestration UI.
- `src/lib/autoCompose.ts`, `autoLayout.ts`, `semanticSelection.ts` — чистая локальная сборка.
- `src/lib/llmSelection.ts` — клиентский вызов proxy и повторный whitelist.
- `server/` — конфигурация, OpenAI-compatible запрос, строгий контракт и HTTP API.
- `public/assets/manifest.json` и `public/assets/*.svg` — извлечённая библиотека.
- `src/data/examples.ts` — три демонстрационных сцены.
- `examples/` — три готовых SVG, экспортированных через интерфейс, и краткая памятка по их проверке.

## Ограничения

- Реальный внешний LLM зависит от совместимости и настроек выбранного провайдера; архив не содержит API key. Проверен локальный HTTP mock, но OpenRouter заработает только с собственным ключом и выбранной моделью проверяющего.
- Локальная эвристика ограничена словарём текущей библиотеки и для неизвестной темы может выбрать явно помеченный нейтральный набор.
- Надёжно извлечён подтверждённый набор из 20 объектов; неоднозначные элементы не выдаются за assets.
- Совместимый endpoint должен поддерживать формат OpenAI `chat/completions` и JSON response format.
- Ручные перемещение и вращение намеренно не ограничиваются границами: пользователь может частично вывести слой за холст.
- При последовательной смене сильно различающихся aspect ratio сцена каждый раз вписывается равномерно и может стать меньше, хотя пропорции не искажаются.
